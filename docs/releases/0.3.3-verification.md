# 0.3.3 stabilization acceptance

**Decision: NOT accepted as a stable release. Candidate prepared for a GitHub draft, not published.**

Acceptance is conjunctive: passing automated tests does not waive native installation, terminal, cancellation or upgrade checks. Missing native coverage blocks release readiness. Results below distinguish actual observations from code inspection and simulations.

## Environment and isolation

- Work started from `main` at `4cbf4ed`, in the approved branch `0.3.3`.
- Installed `/Applications/SSH GUI.app` reports 0.2.0. It was launched through LaunchServices with `SSH_GUI_WORKSPACE` and a dedicated `SSH_AUTH_SOCK` under `/private/tmp`; no user keys or user agent were modified.
- Published 0.3.2 DMG downloaded from this repository's GitHub release. SHA-256 matched published `b76ed1af903e5f6fbc76478caccdea31ed7b67d5b14cc0a69bfa3f676ae8a1d4`. Installed for testing in a separate temporary Applications directory.
- Automated acceptance starts its own agent and optionally a loopback-only sshd. The server forces sessions into a disposable HOME, and the client installer uses an isolated scratch HOME. No external servers are needed.
- Git identity is repository-local `wherespizza <wherespizza@gmail.com>`; no global Git settings were changed. Acceptance was performed locally. On 2026-10-09 the user requested GitHub release preparation: one branch push, a Draft PR and an unpublished release draft are planned; publication and merge remain pending.

## Execution results and remaining gates

- Before fixes: 3/16 targeted error-retention tests failed; subsequent 5/33 targeted dialog/diagnostic/comparison regressions failed; deterministic short-scalar fixture failed.
- Final source checks: **91 frontend tests and 85 Rust tests pass**, including the full lifecycle with `SSH_GUI_LOCAL_NETWORK=1`. TypeScript/Vite production build, Rust formatting, release metadata check and `git diff --check` pass. Additional regressions cover focus returning from a native picker and refusal of truncated structured command output. No functional source edits followed these checks. The subsequently approved signing configuration was rebuilt and its packaged artifacts were verified separately below.
- PTY tests run the exact generated terminal wrapper and exercise correct/wrong fixture passphrase, Ctrl+C, duplicate submission, explicit unavailable agent, successful exit without fingerprint, lifetime/confirmation, and restart recovery. They do not test macOS automation permission or Terminal.app UI.
- Native Terminal.app input is blocked by the computer-use tool; user manual verification remains required. This is not an application permission grant that the agent can silently bypass.
- iTerm2, Alacritty and kitty were not installed in the inspected user environment. Adapter argument unit tests do not count as their mandatory native acceptance.
- Native observations on the first 0.3.3 candidate extracted from DMG: clean empty workspace; reading copied 0.2.0 keys; in-place replacement of a temporary 0.3.2 application; retained selected screen, key fingerprints and saved tag/purpose; plain-key removal/addition; generation; settings runtime information; system file selection with encrypted duplicate rejection and Escape cancellation; host creation and effective configuration diagnostics. Pre-existing fixture file digests were unchanged (6 files for 0.3.2, 5 for 0.2.0).
- Settings and generation/import dialogs were visually checked at 1024×680 and 800×560; import content scrolls at minimum height. This is partial screen/dialog coverage, not the full native matrix.
- These launches used LaunchServices with explicit fixture workspace/socket, not dev PATH. Pure Finder/Dock fresh launches and the complete upgrade/restart/error matrix remain unverified. Later code changes (focus edge case, host labels, subprocess output-limit guard and npm dependency patch) were fully retested/rebuilt but do not inherit a fictitious native pass for the final binary.
- The UI automation tool later confused copies sharing the same bundle identifier and returned a different instance without the isolated-workspace banner. No actions were taken on its real key data; native interactions stopped. Further native work must first establish unambiguous instance selection.
- Native directory selection, full profile/repository-access/rotation/recovery matrix, protected terminal input and each advertised adapter still require concrete passing evidence. Any unresolved mandatory item blocks “stable”.
